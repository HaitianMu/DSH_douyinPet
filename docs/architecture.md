# 工作流程与模块

~~~mermaid
flowchart TD
    A[手动启动或已启用的定时] --> B[简短唤醒词]
    B --> C[读取独立人格和小提示表]
    C --> D{昨日是否有日记}
    D -- 没有 --> E[按日期检索真实经历]
    E --> F[私人日记与短公开草稿落库]
    D -- 已有 --> G[按开启的来源浏览]
    F --> G
    G --> H[快筛并截帧：OCR / 可选视觉]
    H --> I[实际内容归档为版本来源]
    I --> J[话题检索 RAG 与人格上下文]
    J --> K[挑选视频与撰写日报]
    K --> L{值得分享给谁}
    L --> M[结合亲戚名单与已知偏好写草稿]
    M --> N[监护人审核 / 明确开启的自动模式]
    N --> O[重新核验人格、证据、目标和配额]
    O --> P[宿主预占次数后执行账号动作]
    K --> Q[从具体经历形成可修订认识]
    P --> Q
    Q --> R[必要时调整人格并保存原因和历史]
    R --> S[整理最多8行小提示表]
    S --> T[(独立 SQLite 长期库)]
    T -. 下轮按需检索 .-> C
~~~

图示描述浏览值班轮。另有低频消息轮和每日日常轮：消息轮只核验名单中的互关、读取新来信并起草回复；日常轮只按今天真实归档写日记，将 `publicText` 排入待发件箱。宿主按审核方式投递文字或生成本地文字图卡，再尝试上传发布。没有看清画面就不推荐；登录失效或验证时停止外部动作，仍可写本地回顾。聊天和图文页面适配仅经离线验证，AI 生图尚未接入。

## 三层数据

| 层 | 内容 | 读取方式 |
| --- | --- | --- |
| 原始与长期归档 | 画面识别记录、新来信上下文、监护人补充、日记、认识、亲戚偏好 | 按话题/日期检索，再按 source 读全文 |
| 可修订人格 | 表达、兴趣、习惯等当前值与全部历史版本 | 每次主体行动前读取 |
| 小提示表 | 当前关注、待办、待验证判断、表达提醒 | 随默认上下文读取；超期或来源修订后失效 |

私人日记不是公开文案。公开文字单独保存，不能直接搬运家人隐私。OCR、视觉描述和推断均可能出错，来源可追溯只代表知道判断从何而来。

## 权限与失败处理

模型使用独立工具集合，没有收藏、发评论、修改监护人设置或运行 shell 的工具。人格更新字段有限制，作息描述不等于修改实际定时器。亲戚的喜好记录不能变成发送授权。

草稿要求本轮实际读到的视频证据和新鲜的 draft 凭据；发送前重新检查人格与来源版本。一般生成凭据有效30分钟，宿主审核发送最多使用24小时内的凭据，过期需重新生成。

主动文字草稿绑定本轮画面来源；回复绑定账号、对象、最后一条新来信的稳定 ID 和原文；日常绑定当日版本的公开文案。首次消息检查和历史不连续时仅建基线，不回复历史。每轮最多处理 3 名名单对象，轮转位置与基线分别持久化；新来信归档只带最近 8 条上下文，供文本模型判断。待发送前再核验账号、互关、对话是否变化、输入内容、开关、来源和配额。正文输入后与最终发送前均检查对话变化。

每日日常到点写今天，发布权限后来打开也能补排队；失败至少隔 30 分钟重试准备。只有从未尝试发送的日常草稿可以更新公开版本并回到待审；被丢弃、发送过或结果不明的日常不会复活。消息轮按 10–120 分钟间隔运行，社交导航和动作之间至少保留 60 秒间隔。宿主串行协调浏览、登录、审核发送和迁移，模型没有直接发送或发布工具。

配额在浏览器动作前预占。发送中断或页面无法确认时保存 sending/unknown，计入次数，不自动重发。昵称必须唯一精确匹配。收藏在切换前登记尝试，避免下一轮把不确定的收藏反向取消。

同一个宿主同时只跑一轮；信箱写入加锁、SQLite 使用事务，不能因此推断多个独立 DSH 宿主共享一个浏览器的操作也安全。请勿让多份宿主共同操作同一运行目录。

内容请求至少间隔10秒，每批最多3条，推荐与关注不足时不连续翻页凑数。视频静音、1倍正常播放，按时间取样并至少停留30秒；停留时间可设30–120秒，请求间隔可设10–60秒。`browse-pacing.json` 用短文件锁更新实际可用时间，等待在锁外执行，重启仍保留间隔；同实例浏览操作串行。截帧期间定期检查验证，捕获截图后再次检查；验证和HTTP 403/429抛出中止，MCP阻止本轮后续浏览、挑选和草稿，仅允许本地收尾。浏览器自身加载的资源不由该间隔控制。
